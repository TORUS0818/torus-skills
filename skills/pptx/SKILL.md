## スライドの基本思想

**スライドはコミュニケーションツールである。** 情報を並べる場所ではなく、読み手にメッセージを届ける道具。すべてのスライドには読み手が存在し、伝えるべきメッセージがある。

### 1スライド1メッセージ

スライドを作る前に「このスライドで伝えたいことは何か？」を1文で答える。1文で答えられないなら、スライドを分割する。

### スライドの7要素

すべてのスライドは以下の7要素で構成される。全要素が毎回必要ではないが、構造はデッキ全体で一貫させる。

| # | 要素 | 役割 | 位置 |
|---|------|------|------|
| 1 | **タイトル** | スライドの題目 | 上部、太字 |
| 2 | **メッセージライン** | 読み手に伝える最重要ポイント — そのスライドの結論 | タイトル直下、目立つ位置 |
| 3 | **サブメッセージ** | メッセージラインの補足 | メッセージライン下 |
| 4 | **ボディ** | メッセージを裏付ける根拠（表・グラフ・概念図・テキスト） | 中央エリア、最大スペース |
| 5 | **注釈** | 補足事項、前提条件、注意書き | 下部左、小さく |
| 6 | **出所** | データの引用元・情報源 | 下部左、注釈の下 |
| 7 | **ページ番号** | ナビゲーション | 下部右 |

**メッセージラインが最も重要。** セクションラベルではなく、結論を述べる完全な文にする。読み手はメッセージラインだけでスライドの要点を理解できるべき。

- 悪い例: 「売上概要」（これはタイトルであってメッセージではない）
- 良い例: 「Q3売上はAPAC拡大を主因にYoY 15%成長」

### ボディの4つの表現型

メッセージを最も効果的に伝える型を選ぶ：

| 型 | 使う場面 |
|----|---------|
| **表** | 複数次元のデータを比較するとき |
| **グラフ** | トレンド、割合、分布を示すとき |
| **概念図** | 関係性、フロー、構造を説明するとき |
| **テキスト** | 叙述的な説明が不可欠なとき（控えめに使う） |

ビジュアル型（表・グラフ・概念図）を優先する。テキストが多い場合はAppendixに移すことを検討する。

### デッキ全体の構成: 4メッセージフレームワーク

デッキを構成するとき、以下の4つのメッセージ型でスライドを整理する：

1. **現状認識** — いま何が起きているか？
2. **問題提起** — 何が課題か？
3. **解決策** — 何をすべきか？
4. **期待効果** — 何が改善されるか？

### 着手前のプロセス

スライド作成は「作業」であり、重要なのは「考える時間」。PowerPointを開く前に：

1. **メッセージを整理する** — 各スライドで伝えたいことを箇条書きにする
2. **構成を決める** — 4メッセージフレームワークに沿ってスライドの順序を組む
3. **下書きする** — 紙やメモでレイアウトの骨格を決める
4. **それから作る** — ここで初めてツールを使う

## デザインシステム

**Tech-minimalist but information-heavy. Clean, sharp, and authoritative.** スライドは商品 — 内容だけでなく見た目の美しさと分かりやすさも重視する。高い情報密度を保ちつつ、余計な装飾を排した「知的で信頼感のある」印象を目指す。

### カラーパレット

**白背景。黒テキスト。Deep Royal Blue のアクセント。グレーの階調でデータ階層を表現。**

| 役割 | Hex | 用途 |
|------|-----|------|
| **背景** | `FFFFFF` | **全スライド白背景**（表紙・Thank You含む） |
| **テキスト** | `1A1A1A` | タイトル、本文、テーブル本文 |
| **アクセント** | `002B5C` | Deep Royal Blue — チャート/グラフの主色、テーブルヘッダー、カード上線/左バー、キーワード強調 |
| **サブテキスト** | `6B7280` | メッセージライン、補足テキスト、注釈、出所 |
| **グレー1** | `9CA3AF` | チャートの副色、非強調データ |
| **グレー2** | `D1D5DB` | テーブル罫線（fine hairline）、セパレーター、ボーダー |
| **グレー3** | `F3F4F6` | カード背景、ゼブラストライプ |
| **データ: マイナス** | `C53030` | テーブル内のネガティブデータ（テキスト色のみ） |
| **データ: プラス** | `1B7A3D` | テーブル内のポジティブデータ（テキスト色のみ） |

**カラー使用ルール:**
- **全スライド白背景**。ダーク背景スライドは使わない
- **アクセント色 (`002B5C`) は1色のみ**。チャート、テーブルヘッダー、カード構造、キーワード強調すべてこの1色
- チャート・グラフの色は `002B5C` + `9CA3AF` + `D1D5DB` のグレー階調。**2-3色**に限定
- 赤と緑は背景やバーに使わない。テーブル内テキスト色としてデータの意味を示す場合のみ

### タイポグラフィ

セリフ体の見出しで「プレミアムなファイナンシャルレポート」の印象を作り、サンセリフ体の本文でデータを読みやすくする。

| 要素 | フォント | サイズ | ウェイト | 色 |
|------|----------|--------|---------|-----|
| スライドタイトル | Georgia | 26pt | Bold | `1A1A1A` |
| メッセージライン | Arial | 12pt | Regular | `6B7280`（タイトルより控えめに） |
| 本文 | Arial | 11-12pt | Regular | `1A1A1A` |
| テーブルヘッダー | Arial | 10-11pt | Bold | `FFFFFF`（`002B5C`背景） |
| テーブル本文 | Arial | 10-11pt | Regular | `1A1A1A` |
| チャートラベル/数字 | Arial | 10-12pt | Regular | `6B7280` |
| 注釈・出所 | Arial | 7-8pt | Regular | `6B7280` |
| ページ番号 | Arial | 8pt | Regular | `6B7280` |
| 数値コールアウト | Georgia | 36-48pt | Bold | `002B5C` |
| カード内番号 | Georgia | 20pt | Bold | `002B5C` |

- 日本語テキストには **Meiryo** をフォールバックとして使用
- テキストは**左揃え**。中央揃えは表紙タイトルとThank Youのみ
- 強調は**ボールドのみ**。イタリック、下線、複数フォントファミリーの併用は避ける
- タイトルは全スライドで統一サイズ (26pt)、**2行以内**
- **タイトル内のキーワード強調**: 重要な1-2語のみ `002B5C` で着色（全体ではなく部分的に）

### スライドタイプ

**全スライド白背景。** セクション区切りは独立スライドではなく、コンテンツスライド内のタイトルで表現する。

| タイプ | 主要要素 |
|--------|---------|
| **表紙** | プレゼンタイトル（Georgia 40pt, `1A1A1A`）、サブタイトル、日付・著者、出典 |
| **コンテンツ** | タイトル(26pt) + メッセージライン(12pt, グレー) + ボディ + 出所 + フッター |
| **データ/テーブル** | タイトル + メッセージライン + テーブル/チャート（スライドの70-80%）+ 出所 |
| **数値コールアウト** | タイトル（キーワード色強調）+ 大数字カード3列（`002B5C`の36pt数字 + ラベル + 説明） |
| **結論・推奨事項** | タイトル（キーワード色強調）+ 番号付きリスト（番号`002B5C`、本文黒）+ 区切り線 |
| **Thank You** | 中央「Thank You」（Georgia 48pt, `1A1A1A`）+ サブタイトル + 出典 |

### レイアウト原則

**高情報密度とホワイトスペースの両立。** 情報を詰め込みつつ、グリッドベースの配置と一貫したスペーシングで読みやすさを確保する。

- **左右マージン**: 0.7"（全コンテンツのx開始位置を揃える）
- **コンテンツブロック間**: 0.3-0.5" の一貫した間隔
- **左→右の視線誘導**: コンテンツは左から右への流れを意識
- **グリッドベースの配置**: すべての要素を見えないグリッドに揃える。「感覚」で配置しない
- **マルチカラムレイアウト**: 実際のビジネス分析デッキのように情報を詰め込む。空っぽのカバーページのような見た目にしない

**共通フッター:**
- y=5.1" にグレーのhairline区切り線 (0.3pt, `D1D5DB`)
- y=5.15" 右端にページ番号 (8pt, `6B7280`)
- y=4.85" 左端に「Source: 出典テキスト」(7pt, `6B7280`)

**カードスタイル:**
- 背景色: `F3F4F6`（shadowは使わない）
- 上辺にアクセント線 (`002B5C`, 0.04"厚) または左辺にアクセントバー (`002B5C`, 0.06"幅)
- ヘッダー部分を `002B5C` で塗り、白テキストにするパターンも有効
- **カードヘッダーの色は `002B5C` に統一する**

**Key Insightボックス:**
- 背景: `F3F4F6`、左端にアクセントバー (`002B5C`, 0.06"幅)
- テキスト: 11pt Arial Bold, `1A1A1A`

**レイアウトパターン:**

| パターン | 構成 | 使い分け |
|---------|------|---------|
| **フルチャート型** | タイトル(上) + チャート(70-80%) + 出所(下) | データ中心のスライド |
| **2x2カード型** | タイトル(上) + 4枚カード(左バー付き) + 出所(下) | 4項目の比較・分類 |
| **3カラムカード型** | タイトル(上) + 3枚カード(ヘッダー付き) + 出所(下) | 3つの戦略・選択肢 |
| **2列テーブル型** | タイトル(上) + 左右にテーブル + 出所(下) | 2カテゴリの比較 |
| **数値コールアウト型** | タイトル(キーワード色強調) + 3列カード(大数字+ラベル+説明) | KPI、主要指標 |
| **プロセスフロー型** | タイトル(上) + 横並びカード(番号+矢印) + 出所(下) | ワークフロー、手順 |
| **番号付きリスト型** | タイトル(キーワード色強調) + 番号(青)+テキスト+区切り線 | 推奨事項、ガイドライン |

### チャート・グラフのルール

- **グリッドライン、3D効果、過剰な装飾を排除**する
- 凡例よりも**チャート上の直接ラベル**を優先
- 色は `002B5C` + グレー階調 (`9CA3AF`, `D1D5DB`) のみ
- fine hairline borders をテーブルとグラフに使う
- グラフの線は**precise vector lines** — 太すぎず、正確で鋭い線を使う
- 出典を必ず下部に明記
- **推奨するチャートタイプ**: stacked bar chart, waterfall chart, line graph, 100%横棒グラフ
- 棒グラフは差分矢印（例: -60%）を挿入してギャップを数値で言語化

### フレームワーク図

データだけでなく、**構造化されたフレームワーク図**もスライドの重要な要素。

- **2x2マトリクス**: thin, clean lines で構成。軸ラベルを明確に
- **プロセスフロー図**: 3-5ステップ、方向矢印、簡潔なラベル
- **階層図・ツリー図**: 関係性や分類を視覚化
- すべてfine hairline（`D1D5DB`）で構成し、装飾的な太線やグラデーションは使わない

### アイコン・ビジュアル

- アイコンは**モノクロ、シンプル、ミニマリスト**
- 装飾的なアイコンは使わない。情報を補助する目的のみ

### 避けるべきこと（よくあるミス）

- **ダーク背景のスライドを作らない** — 全スライド白背景
- **色を使いすぎない** — `002B5C` + 黒 + グレー階調。それ以外は原則不要
- **本文を中央揃えにしない** — 段落とリストは左揃え。中央揃えは表紙タイトルとThank Youのみ
- **スペーシングをランダムにしない** — 0.3" か 0.5" を決めて一貫して使う
- **全スライドのスタイルを統一する** — 1枚だけ凝って他を放置しない
- **テキストだけのスライドを作らない** — 表、グラフ、概念図等のビジュアル要素を追加する
- **テキストボックスのパディングを忘れない** — `margin: 0` を設定するか、パディング分をオフセットする
- **低コントラストの要素を使わない** — テキストとアイコンが背景に対して十分なコントラストを持つこと
- **タイトル下にアクセントラインを絶対に使わない** — AI生成スライドの典型。代わりにホワイトスペースを使う
- **注釈・出所を省略しない** — 引用データや外部情報は必ず出所を記載
- **メッセージラインを省略しない** — すべてのコンテンツスライドにメッセージラインを入れる
- **グラデーション、装飾的シェイプを使わない** — フラットでクリーンに
- **アニメーションや特殊効果は使わない** — 情報で勝負する

## QA（必須）

**問題があることを前提にする。それを見つけるのがあなたの仕事。**

最初のレンダリングはほぼ間違いなく正しくない。QAは確認作業ではなくバグハント。初回の検査で問題がゼロなら、十分に見ていない。

### コンテンツQA

```bash
uv run python -m markitdown output.pptx
```

内容の欠落、タイポ、順序の誤りを確認する。

**テンプレート使用時は、プレースホルダーテキストの残りを確認:**

```bash
uv run python -m markitdown output.pptx | grep -iE "xxxx|lorem|ipsum|this.*(page|slide).*layout"
```

grepで結果が出たら、成功を宣言する前に修正する。

### ビジュアルQA

**サブエージェントを使うこと** — 2-3枚のスライドでも。コードを見続けた目は期待通りのものを見てしまい、実際のものを見逃す。サブエージェントは新鮮な目を持っている。

スライドを画像に変換し（[画像への変換](#画像への変換)を参照）、以下のプロンプトを使用：

```
これらのスライドを目視検査してください。問題があることを前提にして、見つけてください。

確認項目:
- 要素の重なり（テキストがシェイプを貫通、線が文字を横切る、要素の積み重なり）
- テキストのオーバーフローまたはエッジ/ボックス境界での切れ
- 1行用に配置した装飾線がタイトル折り返しで2行になった場合のズレ
- ソース引用やフッターがコンテンツと衝突
- 要素が近すぎる（< 0.3" の間隔）またはカード/セクションがほぼ接触
- 不均等な間隔（一箇所に大きな空白、別の箇所が窮屈）
- スライド端からのマージン不足（< 0.5"）
- カラムまたは類似要素の不整列
- 低コントラストのテキスト（例: 薄い灰色のテキストにクリーム色の背景）
- 低コントラストのアイコン（例: 薄いグレー背景に薄いアイコン）
- テキストボックスが狭すぎて過度な折り返し
- プレースホルダーコンテンツの残り

各スライドについて、軽微なものも含めて問題や懸念点をリストアップしてください。

以下の画像を読み取って分析してください:
1. /path/to/slide-01.jpg（期待: [簡単な説明]）
2. /path/to/slide-02.jpg（期待: [簡単な説明]）

軽微なものも含め、発見したすべての問題を報告してください。
```

### 検証ループ

1. スライド生成 → 画像に変換 → 検査
2. **発見した問題をリストアップ**（ゼロなら、もっと批判的に見直す）
3. 問題を修正
4. **修正したスライドを再検証** — 1つの修正が別の問題を生むことが多い
5. 完全なパスで新しい問題が出なくなるまで繰り返す

**少なくとも1回の修正→検証サイクルを完了するまで成功を宣言しない。**

## 画像への変換

ビジュアル検査のためにプレゼンを個別のスライド画像に変換する：

```bash
uv run python scripts/office/soffice.py --headless --convert-to pdf output.pptx
pdftoppm -jpeg -r 150 output.pdf slide
```

これにより `slide-01.jpg`, `slide-02.jpg` 等が作成される。

修正後に特定のスライドだけ再レンダリングする場合：

```bash
pdftoppm -jpeg -r 150 -f N -l N output.pdf slide-fixed
```
