## §2 背景と手法

### 形式的定義

```
基本:   E ← P_LLM(x + C)
信頼性: R ← f_R(P_LLM, x, C)
```

- **E**: 最終評価（スコア、選択、ラベル、文章）
- **P_LLM**: LLMの確率関数
- **x**: 評価対象の入力データ
- **C**: コンテキスト（プロンプトテンプレート、対話履歴）
- **R**: 一貫性・ロバスト性・人間との整合性を保証する評価
- **f_R**: バイアス軽減・変動性制御・敵対的入力への頑健性を高める制約

### 4つのプロンプト設計手法（§2.1 ICL）

| 手法 | 内容 | 補足 |
|------|------|------|
| **スコア生成** | 離散（1-5, 1-10）or 連続（0-100）のスコアを生成 | Likert尺度で多次元評価も可能 |
| **Yes/No判定** | 二値判断 | フィードバックループの中間プロセスで使用 |
| **ペアワイズ比較** | 2つの回答を比較して優劣を判定 | 人間との整合性がスコア方式より高い |
| **多肢選択** | 複数の選択肢から最適なものを選択 | 使用頻度は低い |

### モデル選択（§2.2）

- **汎用LLM**: GPT-4 が最も高い精度と安定性
- **ファインチューニングLLM**: PandaLM、JudgeLM、Auto-J、Prometheus 等
  - 典型的な3ステップ: データ収集 → プロンプト設計 → ファインチューニング
  - 課題: 汎化性能の限界、バイアスの継承

### 後処理（§2.3）

LLM Judgeの出力から評価結果を取り出す3つの方法。

1. **特定トークンの抽出**: 正規表現等でスコアやラベルを抽出。制約付きデコーディング（出力を評価値トークンのみに制限）で最大100倍高速化。OSSモデルのローカル実行向け
2. **出力logitsの正規化**: Yes/No等の離散判定を、内部logitsから確信度付きの0-1連続値に変換。APIでは利用が限定的
3. **文の選択**: 長い評価文から実質的な評価コンテンツを含む文だけを選別。推論木構築等の手法。研究寄り

### 4つの評価パイプライン（§2.4）

1. **モデル評価**: LLMを自動プロキシとして使い、他のモデルを評価
2. **データ評価**: データアノテーションの自動化。RLHF、DPO 等との連携
3. **エージェント評価**: エージェント全体、またはフレームワーク内の特定段階の評価
4. **推論/思考の評価**: 訓練時（報酬モデル）とテスト時（Best-of-N選択）の両面

### クイック実践ガイド（§2.5）

4段階のプロセス：
1. **思考**: 評価目的の定義、人間評価手法の理解、信頼できる評価例の特定
2. **プロンプト設計**: スコア次元の指定、相対比較の重視、効果的な例示の作成
3. **モデル選択**: 強力な推論力と指示追従能力を持つ大規模モデルの選定
4. **出力標準化**: 構造化フォーマット（JSON等）の使用

## §3 改善戦略

形式的定義の3つの変数（C, P_LLM, E）に対応する3つの戦略。

### 3.1 プロンプト設計戦略（Cの最適化）

#### タスク理解の向上
- **Few-shot Prompting**: 高品質な評価例を提示
- **評価ステップの分解**: G-Eval 等。読解→分析→スコアリングを順次ガイド（CoT活用）
- **評価基準の分解**: Branch-Solve-Merge が並列サブタスクに分割
- **コンテンツのシャッフル**: 位置バイアス軽減のため評価対象の順序をランダム化
- **評価タスクの変換**: スコアリングをペアワイズ比較に変換し安定性向上（PARIS）

#### 出力フォーマットの標準化
- 構造化出力の制約（JSON形式等）
- 説明付き評価（スコア + 理由）

### 3.2 能力強化戦略（P_LLMの改善）

- **特化ファインチューニング**: 評価専用のデータセットでLLMを追加学習
- **フィードバック駆動型反復改善**: 人間のフィードバックやGPT-4のフィードバックで反復的にLLMを改善

### 3.3 最終出力最適化戦略（Eの改善）

#### 多ソース統合
- **複数ラウンドの平均**: 同じ評価を複数回実行してスコアを平均
- **複数LLMの投票**: 複数モデルに評価させて多数決
- **階層的評価**: 弱→強モデルへの信頼度ベース遷移

#### 直接出力最適化
- **スコア平滑化**: トークン確率を重みとしてスコアを調整
- **自己検証**: 評価結果に対する確信度をLLMに問い、検証パスしたもののみ保持

## §4 LLM-as-a-Judge の評価（メタ評価）

### 4.1 人間判断との一致を測る指標

| 指標 | 内容 |
|------|------|
| **Percentage Agreement** | 単純な一致率 |
| **Cohen's Kappa** | 偶然の一致を補正した信頼性指標 |
| **Spearman's correlation** | 順位相関 |
| **Precision/Recall** | 分類問題としてのアプローチ |

### 4.2 バイアスの詳細分類

原典（Zheng et al.）で発見された3つに加え、さらに多くのバイアスが整理されている。

#### タスク非依存バイアス
- **多様性バイアス**: 特定の人口統計グループ（性別、人種等）に対するバイアス
- **文化バイアス**: 異文化の表現に対する誤解
- **自己強化バイアス**: 自身が生成した回答を好む傾向

#### 判断固有バイアス
- **位置バイアス**: GPT-4 は第1位置、ChatGPT は第2位置を好む
- **Compassion-fade バイアス**: モデル名の影響（「gpt-4」ラベルで高スコア）→ 匿名評価が必要
- **スタイルバイアス**: 絵文字付き等の視覚的に魅力的なコンテンツへの偏り
- **長さバイアス**: より長い回答を好む傾向（= Verbosity Bias）
- **具体性バイアス**: 権威的引用・数値・専門用語を含む回答への偏り。ハルシネーションを助長

### 4.3 敵対的攻撃

- **敵対的フレーズ挿入**: 攻撃フレーズでスコアを不当に引き上げ
- **Nullモデル攻撃**: 質問と無関係な固定応答でも高い勝率を達成
- **多数派意見攻撃**: 「90%がこちらが良いと考える」等の追加でスコア操作
- 防御策はまだ限定的

### 4.4 実証実験の重要な発見

#### モデル比較
- **GPT-4-turbo**: 全次元で最高性能。人間との一致率 61.54%、位置一貫性 80.31%
- **Qwen2.5-7B-Instruct**: オープンソース最高。GPT-3.5-turbo を多くの次元で上回る
- **推論特化LLM（o1-mini, DeepSeek-R1 等）**: GPT-4-turbo と競合するが、人間整合性の改善は期待ほど顕著ではない

#### 改善戦略の効果比較（GPT-3.5-turbo ベース）

| 戦略 | 効果 |
|------|------|
| **説明付き（w/ explanation）** | **悪影響**。深層バイアスを助長 |
| **自己検証（w/ self-validation）** | **効果最小限**。LLMの過信が原因 |
| **多数決@5回** | **明確な効果あり**。最も推奨 |
| **平均スコア@5回** | **効果なし**、一部で悪影響 |
| **複数LLM投票** | LLMの選択に強く依存。弱いモデルが全体を低下 |

## §5 応用領域

### 機械学習
- **NLP/テキスト生成**: 対話、要約、ストーリー作成の評価。ハルシネーション検出、安全性評価
- **推論**: サンプルレベル（ペアワイズ自己評価）とステップレベル（Process Reward Models）
- **検索/RAG**: 文書ランキング、RAG パイプラインの品質評価
- **ソーシャルインテリジェンス**: LLM エージェントの社会的相互作用の評価
- **マルチモーダル**: 画像+テキストの統合評価。ペアワイズは高性能だが絶対スコアリングは課題

### 専門ドメイン
- **金融**: クレジットスコアリング、ESG評価、トレーディングシグナル精製
- **法律**: 法的推論の評価、判例との整合性チェック
- **科学**: 臨床推論（Cohen's kappa = 0.79 で人間レベル）、数学（GSM8K, MATH）
- **教育**: 自動エッセイ採点、ソフトウェアエンジニアリング評価

## §6 課題

1. **信頼性**: プロンプトの微妙な変更で結果が不安定。過信と自己強化。モデルのバージョン依存
2. **ロバスト性**: 敵対的攻撃への脆弱性。オープンソースモデルが特に脆弱
3. **バックボーンモデルの限界**: 抽象的推論と因果推論にまだ限界がある
4. **解釈可能性**: 評価プロセスがブラックボックス。ハイステークス領域での信頼を制限
5. **メタ評価と時間的一貫性**: 評価者自体を検証するベンチマークが不足。「評価ドリフト」問題
6. **倫理的影響**: バイアス増幅、アカウンタビリティ欠如、コンテンツの均質化リスク

## §7 将来方向（10の研究方向）

1. **推論中心の判断**: LLM-as-a-Judge は評価ツールだけでなく推論能力を強化する機構へ
2. **理論的基盤の確立**: 経験的ベンチマーク依存から、統計学・測定理論に基づく形式化へ
3. **より信頼性の高いシステム**: 敵対的訓練、不確実性定量化、human-in-the-loop
4. **MLLM-as-a-Judge**: テキスト・音声・画像・動画を統合したマルチモーダル評価者
5. **評価ベンチマークの発展**: ImageNet 規模のメタ評価標準の確立
6. **データアノテーション**: データ不足シナリオでの品質ラベリング
7. **スケーリング**: RLHFの大規模嗜好ラベル生成、半自動ワークフロー
8. **身体知能**: 物理環境でのエージェント行動評価
9. **LLM最適化**: マルチエージェントフレームワークでのガイド
10. **ドメイン固有応用**: 医療（副作用検出）、法律（先例準拠）、教育 等

## 実務上の重要ポイント（実践的推奨事項のまとめ）

1. **モデル選択**: GPT-4 クラスを優先。オープンソースなら Qwen2.5-7B が有力候補
2. **評価形式**: ペアワイズ比較がスコアリングより信頼性が高い
3. **バイアス軽減**: 位置スワップ + 多数決@5回が最も効果的
4. **出力設計**: 評価と説明の同時生成は避ける。構造化出力（JSON等）を使用
5. **メタ評価**: モデル選択前に小規模なバイアスプロファイリングを実施
6. **スコア集約**: 平均やベスト選択より多数決が優れる
7. **ロバスト性**: 敵対的攻撃への脆弱性を認識し、人間監督を維持
